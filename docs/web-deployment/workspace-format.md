# Workspace format v1

The provider-neutral folder contains `libreflow-workspace.json`, encrypted `record-UUID.json` events, and encrypted `asset-SHA256.json` chunks. UUIDs are generated with Web Crypto. The manifest contains only schema, random workspace ID, creation timestamp and wrapped encryption-key parameters. It contains no project names, credentials or plaintext keys.

A random 256-bit data key encrypts every event and managed asset using AES-256-GCM with unique random 96-bit IVs and context-bound authenticated data. A passphrase of at least 12 characters derives the wrapping key using PBKDF2-SHA256 at 600,000 iterations, a 128-bit salt, and Web Crypto. This browser-native KDF is a documented compromise instead of shipping an unreviewed Argon2 implementation. Keys and tokens remain in memory. Losing the passphrase means losing access; there is no host-side recovery key. Providers can still observe file count, encrypted sizes, timestamps and equality of chunk hashes; encryption does not hide all traffic metadata.

Each decrypted event has schemaVersion, UUID id, type, entityId, parent event IDs, timestamp, value, and a canonical-JSON SHA-256 integrity hash. Supported types cover project, image, model, annotation, review, batch, dataset, immutable version, audit, session and private integration configuration. Annotation events are partitioned per image rather than per project. Old events are never overwritten. Dataset version entities cannot be updated. Concurrent leaf events constitute a recoverable conflict; resolution explicitly appends an event with all conflicting parents. Provider revision tokens are available in adapters, but append-only event identity avoids depending on non-atomic provider check-then-write operations. This supports single-user workspaces and preserves concurrent states; it is not a multi-user live-collaboration protocol.

Managed assets are encrypted in 4 MiB chunks; each chunk has a plaintext SHA-256 checked after decryption. A SHA-256 over the canonical chunk hash/size list binds ordering and lengths. `contentHash` is this versioned chunk-list digest, **not** the conventional full-file SHA-256. Reads yield chunks. Linked assets retain provider ID/revision and optional full-file hash; source-provider authorization must remain available. Linked files are not encrypted by LibreFlow and may change independently.

Encrypted pending events are written to IndexedDB before remote transfer. Failed/offline writes remain pending for retry; keys must be unlocked again after a crash. IndexedDB never stores plaintext values or OAuth tokens. Cloud/provider storage remains the source of truth. The current metadata sync scans immutable record listings and is not optimized for millions of events. Do not advertise unlimited scale.

Portable v1 export preserves encrypted event and asset bytes and the wrapped key. Import validates schema, decrypts/verifies every record before writing, and requires an empty destination. Managed assets resolve by hash filename, so opaque provider IDs can change during migration. Linked assets retain their original provider dependency. The current JSON backup API buffers the export and is intended for bounded workspaces; large-workspace streaming export is not yet implemented. Unsupported schema versions fail explicitly; there are no older web schemas to migrate.
