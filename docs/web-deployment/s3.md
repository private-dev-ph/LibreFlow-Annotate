# User-machine S3 companion storage

The S3 provider keeps all bucket access between the browser and the user's paired loopback companion. The browser sends workspace bytes to `127.0.0.1:8787`; the companion uses its own S3 client and AWS credentials. Neither S3 credentials nor the endpoint URL are accepted from browser requests, and the web host receives no S3 file payloads.

## Companion setup

Install the optional, pinned S3 dependency in the companion's Python environment when S3 storage is needed. Boto3 and botocore are imported only when an S3 operation is made:

```sh
python -m pip install -r requirements-s3.txt
```

Set these values on the user machine before starting the companion:

| Variable | Required | Meaning |
| --- | --- | --- |
| `LIBREFLOW_S3_BUCKET` | Yes | The one bucket exposed to this adapter. |
| `LIBREFLOW_S3_PREFIX` | No | Root key prefix for this user's workspace. Empty means the whole bucket. |
| `LIBREFLOW_S3_ENDPOINT` | No | S3-compatible endpoint URL for the local companion's client. |
| `LIBREFLOW_S3_REGION` | No | Region for the client; falls back to `AWS_REGION` or `AWS_DEFAULT_REGION`. |

Credentials come from boto3's standard AWS credential chain (including role credentials, environment-based credentials, and shared AWS configuration). Supply them using the machine's normal secure credential mechanism. Do not put credentials or endpoint configuration in the static web app or browser storage.

The route factory is standalone so it can be mounted by the companion application without importing boto3 at module load:

```python
from companion_s3 import attach_s3_routes

# Inside the companion's application factory, after defining its paired
# authorize(request) function and installing its normal HTTP error handling:
attach_s3_routes(app, authorize)
```

The authorization callable must enforce the same origin-bound paired bearer policy as the other companion routes and raise the application's normal HTTP error on denial. Existing request-size middleware should cap bodies at 33 MiB; the S3 routes independently cap stored and read objects at 32 MiB. `attach_s3_routes` accepts an injected boto-compatible client for offline tests or embedding. It returns the backend for health/capability integration. S3 support remains optional when the factory is not mounted.

The browser provider is `createS3CompanionProvider({ companion })` from `public/web/providers/s3-companion.mjs`. The paired companion object supplied to it must expose:

```js
companion.storageRequest(path, {
  method, headers, body, signal, responseType: 'json' | 'bytes'
})
```

That method must use the same in-memory bearer as pairing, target only the fixed loopback companion origin, and parse JSON or return a `Uint8Array` for `responseType: 'bytes'`. The provider does not take a token, fetch function, S3 endpoint, or S3 credential. Its paths are fixed to `/storage/s3/...`.

## Routes and safety

The companion exposes list, stat, raw-byte read/write, and folder creation under `/storage/s3`. `root` is the only bucket workspace ID. Item IDs are URL-safe HMACs of S3 keys using a random process-local secret; a process-local map resolves IDs only after the key was listed or created during that companion process. Restarting the companion invalidates prior S3 IDs, consistent with revoking its paired token. Caller input is never interpreted as an S3 key or path. Names are restricted to one safe path component and every resolved key is checked against the configured prefix.

Object writes require S3 conditional-write support. New objects use `If-None-Match: *` so a concurrent create cannot silently replace an object. Overwrites require the current ETag revision and use `If-Match`; missing revisions and stale revisions fail closed. Endpoints that reject those conditional headers cannot be used for writes. Listing and reads do not provide ranged reads. A folder listing is capped at 100,000 entries and 1,000 continuation pages, and fails instead of looping on a repeated continuation token. Object uploads and downloads are limited to 32 MiB. S3 delete is disabled: the adapter does not issue a read-then-delete sequence or assume that a compatible endpoint's delete precondition is atomic. Folder markers are created conditionally. S3 calls run in worker threads so the async companion can serve other requests while boto3 waits; clients use 5-second connect and 30-second read timeouts with standard retries configured as `max_attempts=3` (three retries after the initial request).

The only network destination involved in S3 access is selected by local machine configuration and used by the companion's boto3 client. The routes do not accept arbitrary URLs, bucket names, endpoint URLs, or credentials, and do not provide a general network proxy.
